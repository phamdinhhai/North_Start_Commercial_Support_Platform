# Browser companion sandbox implementation

Native Manifest V3 extension remains an explicit one-tab/page metadata observer with local export by default. Optional upload requires a trusted HTTPS backend origin, explicit popup consent and an issuer-produced enrollment JSON. The extension requests that origin only through optional host permission. It never contains the issuer secret or calls the issuer enrollment/revoke endpoint.

Load unpacked from `product/src/adapters/browser-companion` in Chrome/Chromium developer mode. Keep all six runtime assets together: manifest.json, popup.html, popup.mjs, worker.mjs, protocol.mjs, upload.mjs. This is an unpacked research build, not a signed store release.

The operator obtains POST /v1/integration/enroll output outside the extension using the backend issuer procedure, then pastes the JSON and HTTPS origin into Optional backend upload. Scope labels must match the fixed signed workspace/connection/account/page grant. Start before a new Pancake websocket opens. Upload/retry sends one oldest record per explicit click to POST /v1/integration/observations with the enrolled bearer token. No background alarm uploads.

The durable local pending request is written before network I/O and retained across worker/browser restart, offline failures and lost ACKs. Only an ACK with receipt ID, stored/duplicate disposition, matching enrollment/capture/sequence and checkpoint, and continuity UNKNOWN removes the oldest record. Conflicts retain evidence and block delivery. 401/403 remove local authority and stop capture; re-enrollment is required. New enrollment cannot relabel a nonempty outbox. Export excludes credentials and pending delivery internals. Disconnect removes the local token and stops capture; issuer-side revoke is separate.

Storage is restricted to trusted extension contexts. Outbox is capped at 1000 metadata records; full capacity stops capture and records a drop. Raw frames are bounded at 256 KiB, backlog at 100 tasks, sockets at 50; outgoing request and ACK at 16 KiB with a 10-second request abort. Message bodies, websocket credentials, cookies and unknown payload fields never enter observations.

Validation on 2026-11-17: companion Vitest 20 tests passed, including VM worker network/offline/restart retry and exact duplicate ACK, page/scope drift, unauthorized/conflict retention, malformed ACK, body/capacity bounds and export privacy. Existing real Chromium MV3 synthetic websocket smoke passed capture, private-text exclusion and browser restart persistence without contacting a provider. Full Vitest: 402 passed, 21 skipped (34 passed files, five skipped); typecheck and Nest build passed. No dependency changes.

Limitations: upload network lifecycle uses mocked HTTP in the worker harness; the real browser smoke covers capture/restart, not a live enrollment/backend roundtrip. No new private/provider captures were made. This implements sandbox transport authority only, not production IAM, provider replay, commercial mutation or a completeness guarantee. Authentication, completeness and continuity remain UNKNOWN. Canonical PM-1 and other open decisions remain unresolved; human PH3/PH4 and L5 gates remain in force.
