# Contact claim API contract for QA

Base `/v1/pilot/leads/:leadId/contact-attempts`. Existing authentication/session/CSRF boundary applies; leadId UUID. GET `?limit=50&after=<nextCursor>` returns `{version,isSynthetic,items,nextCursor?,truth}`. Max100 rows. UUID cursor resolves a workspace/lead-scoped row; history orders by recorded_at then id, including a stable tie-breaker. A foreign/unknown cursor yields no rows. Each item has id, leadId, workspaceId, actor, recordedAt, occurredAt, channel, claimedResult, evidenceRef (nullable/missing), followUpImplication, reason, acquisitionMode=claimed and assertionStatus=claimed. truth contains distinct conversationSource/acquisitionLineage/revenueAttribution objects `{status,value,reason}`. No provider facts imply credit. Cache-Control:no-store.

POST accepts ONLY `{expectedVersion,idempotencyKey,occurredAt,channel,claimedResult,evidenceRef?,followUpImplication,reason}`. expectedVersion positive integer; idempotencyKey nonblank <=128; occurredAt explicit `unknown` or past ISO datetime with zone; channel phone/message/email/other; claimedResult reached/no-answer/left-message/unknown; evidenceRef UUID; followUpImplication and reason nonblank <=2000. Actor/workspace/recordedAt cannot be overridden. Returns201 `{attemptId,version}`. Exact retries return same result even with old expectedVersion. Conflicting key409; stale409 STALE_VERSION; bad input400; unauthenticated401; viewer/demo/nonowner403; foreign lead404. Missing/unrelated proof422; foreign/classification proof403. Optional evidence absence does not deny a human claim.

DOM: #record-contact opens Record manual contact claim; #contact-occurred optional blank=>unknown; #contact-channel; #contact-result; #contact-evidence optional; #contact-follow-up; #reason. #contact-history loads after lead selection and writes/reloads; #commercial-truth displays three concepts with UNKNOWN reasons. #contact-attempts reloads history; #contact-next paginates. No mutation inference: lead stage/work/outcome remain identical after POST. Contact follow-up field explicitly says it does not schedule an action. History uses textContent; test XSS-looking claim text remains inert. Existing dialog version/conflict/reload/double-submit behavior applies.
