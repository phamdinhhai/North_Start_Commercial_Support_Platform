# Provenance security review

Companion to [trust boundary assessment](trust-boundary-assessment.md). Implementation scope: local synthetic trust projection and negative admission checks only. No provider endpoint, webhook receiver, OAuth executor, account, credential, live customer, service permission or schema migration is introduced.

## Current data handling

The existing synthetic surface is admin-only, local/test, OIDC and PostgreSQL gated. Operator authentication and application membership remain distinct from source origin. The offline decoder cannot mint an OIDC operator or provider principal. Lead evidence reads still require lead-scoped authorization. Original payloads are retained only through the established accepted raw-envelope path; metadata quarantine does not retain the utterance. Error responses must remain fixed categorical codes; decoder failures must not return provider bodies, URLs or exception messages.

Operational logging uses the existing key allowlist; unknown `body`, `observation`, token and headers fields are dropped. The new projection excludes raw payload and identifiers. Existing source audit entries record receipt/connection/lead identifiers and categorical disposition/UNVERIFIED status, not message text or credential values. Audit IDs may still be linkable personal data; authorization, retention, export and backups must protect them. This change does not claim raw storage, audit history or database backups are anonymized. Do not restore a backup into a lower-trust environment or retain tokens in dumps. Retention, legal hold, encryption/key custody and erasure across backup/downstream copies remain Gate C prerequisites, not newly invented policy.

## Future live design — not enabled

Provider documentation and pinned sample inspections in [R4.10 social research](../../research/platform-intelligence-r4.10/social-platform-research.md) and [Pancake research](../../research/platform-intelligence-r4.10/pancake-deep-research.md) are offline research evidence. They do not demonstrate current account entitlement. Each provider/version requires current first-party verification and rights evidence before live admission.

1. Keep an OIDC **operator** distinct from a future connection-bound **service principal**. The latter may append observations only for its own active workspace/connection and capability; it cannot read the inbox, impersonate a human, assign roles, claim lead ownership, mutate commercial state, send outbound messages or receive canonical meaning from provider labels. ADR-006 governs any eventual connector identity. No such principal is created here.
2. A future OAuth enrollment must bind redirect URI, state and PKCE where applicable to a short-lived server session, prevent workspace/connection substitution, store credentials only in a vault, and record scope/account/app/version entitlement separately from native event identity. Rotate secrets using versioned key IDs and bounded overlap; revoke connection/capability promptly on token revocation, asset removal or rights downgrade. Existing immutable evidence remains readable under lead policy; revocation never upgrades or rewrites it.
3. Verify provider signatures over the exact bounded raw request bytes **before** parsing or acknowledging provider-authenticated admission. Validate signature format, algorithm, expected length, active key version and connection/account binding. Use constant-time comparison of equal-length decoded MAC bytes; never string equality, browser hashes, hardcoded keys or obsolete sample algorithms. Secret rotation must be versioned and reject expired/revoked keys. A webhook subscription challenge is not message authentication.
4. Signature validity, transport service identity, provider-reported native IDs, local declared mapping, provider attestation and independent corroboration are separate facts. Even a valid signature cannot establish customer identity, canonical commercial truth, acquisition lineage or revenue attribution. Preserve raw evidence and append new verification/correction records rather than mutating historical observation claims.
5. Enforce bounded body size, schema/version allowlists, request deadlines, queue limits, per-connection rate limits and idempotent receipt keys. Timestamp/replay controls must reflect documented provider retry behavior rather than discarding legitimate retries. Lock connection state with append and reject revoked credentials before accepting duplicate receipts. Event identity and message identity remain separate; differing revisions/events preserve their own originals and detect collisions atomically. No unauthenticated request may supply workspace IDs, signing key URLs or credential lookup destinations.
6. Outbound provider network calls need fixed approved endpoints, redirect/DNS/SSRF policy, safe TLS, timeouts and redacted error bodies. SDK debug logs and URL query tokens must never bypass the telemetry allowlist. Backup/restore rehearsals must preserve evidence classification and credential custody without emitting raw data into test artifacts.

Residual live controls are unimplemented by design. No severity claim about a reachable live vulnerability follows from forged synthetic mappings. Any actual regression that permits tenant/lead access bypass, non-admin simulation, trusted provider promotion or live enabling requires immediate correction and explicit evidence in integrated QA.
