# R4.12 operational runbook and acceptance boundaries

This runbook covers fabricated offline synchronization only. It does not approve provider network access, public ingress, customer-data capture or production custody. The Project Owner operates the existing synthetic Sales pilot; agents use new isolated engineering fixtures.

1. Initial configuration: run reviewed additive migrations in a new test database. Create a synthetic source connection scoped to the intended workspace/provider/account. Leave the source feature off unless local/test + OIDC + PostgreSQL guards are satisfied. Do not edit Owner pilot manifests or session configuration.
2. Credentials: configure fabricated in-memory TEST_ONLY custody through an admin context in the harness. Store no token in business rows, source history, URLs, logs or chat. A production credential reference is unavailable until approved vault/KMS custody exists. Inspect metadata/audit only; rotating the version invalidates old principals and revoked entries cannot be revived.
3. Worker start/stop: invoke the bounded `runDurableOfflineSync` harness with explicit page/item/time limits and server-bound authorizeFetch. No daemon or provider client is registered. Stop starting new invocations; admin pause/revoke clears leases and fences future commits. In-flight memory authorization cannot promise instantaneous cancellation.
4. Troubleshooting: inspect `/v1/source-integrations/sync-health` as manager/admin. Source connection revoke takes precedence over stale stream state. Last attempt/commit, checkpoint version/completed, categorical failure, retry eligibility and local receipt/quarantine counts are distinct from external completeness. Lag remains UNKNOWN; failure-history counts are NOT_PERSISTED, not zero.
5. Retry: honor persisted nextRetryAt and bounded retry exhaustion. Timeout/429 degrade the stream; schema/gap/retry exhaustion blocks it. Correct the fabricated adapter contract before resume; never advance a raw cursor manually. Opaque cursor text is not shown in the UI.
6. Quarantine: missing native IDs retain metadata-only unknown state under existing intake policy. Do not relabel it verified or infer an outcome. A committed page containing quarantine is not full provider synchronization. Replay must use the known page key/content and active authorization; no arbitrary public replay/reset endpoint exists.
7. Restore: use `node scripts/restore-rehearsal.mjs` only with explicit disposable `/north_start_ci` (or named engineering `/r412_root`) loopback target. The helper creates new databases itself, verifies16-table HMAC snapshots including checkpoints/deliveries, then verifies source/link/page/delivery replay. Audit attempt append is expected; immutable source/page/delivery history must not change. No real credentials are backed up.
8. Process recovery: `node scripts/sync-recovery-rehearsal.mjs` creates its own disposable database and child fixture, observes exit73 after two commits, restarts to page3, and verifies three receipts/unassigned Leads. This is local recovery evidence, not production RTO/RPO. `scripts/pilot/rehearsal.mjs` is run only against a newly generated agent-owned launcher manifest for actual PG outage testing.
9. Emergency revoke: revoke the stream and source connection, stop future worker invocations, rotate/revoke fabricated credential, verify subsequent fetch/intake refusal and preserved immutable history. Future provider token/subscription revoke must be independently confirmed in an approved sandbox.
10. Cleanup: close only this run's child/browser/app/database resources and stop its generated PostgreSQL cluster. Retain immutable artifacts outside Git as required; never reset/delete Owner pilot resources. Provider cleanup is NOT RUN because no provider resource was created.

Operator acceptance: admin controls succeed; manager reads but control is403; Sales/viewer/demo/anonymous reads are refused; workspace substitution fails; no cursor, lease token, raw body or secret appears in health; pause/revoke remains inspectable; app restart preserves streams; receipts do not create owner/outcome. Independent signed OIDC browser tests exercise these points. Session/draft and legacy LVP regression remain required final lanes.
