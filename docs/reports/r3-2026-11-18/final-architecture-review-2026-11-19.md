## Findings

### A-01 — P1 active-path defect: viewer can invoke pilot mutations

Evidence: `product/src/api/pilot-loop.controller.ts:108` resolves authentication for intake and `:117` ingests without a role mutation gate. Existing-lead POST handlers use `authorizedView` (`:183`, `:201`, `:220`, `:239`, `:259`, `:290`, `:309`). That helper (`:359`) enforces workspace and read access. A viewer assigned as owner or an active recipient can therefore pass the same read/owner checks used by mutations. For example, a viewer can create an owned scenario and then hand it off (`:184`) or record an outcome (`:310`). This contradicts ADR-006's read-only viewer row. This is an exposed manual-loop permission defect, independent of the governed-action feature being disabled.

Recommendation: reject non-demo viewer on every pilot POST before calling the application service; keep demo behavior explicitly isolated and retain existing owner/recipient checks for allowed roles. Verify all POST handlers, no mutation-service call on rejection, unchanged authorized reads and cross-workspace invisibility. A separate remediation agent owns the fix; its review status is recorded below.

### A-02 — P2 latent privacy defect: outcome evidence bypasses ADR-009 digester

Evidence: `product/src/domain/governed-action/action-outcome-assertion.ts:65` computes `rawPayloadHash` with unkeyed SHA-256 over arbitrary `verification.evidence`; the evidence type is unrestricted JSON (`governed-action.types.ts:155`). If a future readback contains a short customer message, telephone number or order code, it produces a guessable, cross-workspace-comparable content hash despite ADR-009. The deterministic assertion identifier at `action-outcome-assertion.ts:19` hashes technical workspace/proposal/sequence identity and is not itself evidence of this privacy violation.

Recommendation: before any real-data governed action, inject a server-side workspace ContentDigester at the application boundary, persist algorithm/kid/value, and give the pure domain mapper an already-derived digest. Alternatively enforce and test a genuinely content-free readback evidence schema. Verify same content differs between workspace keys and key rotation preserves the recorded kid. This does not demonstrate a current customer-data leak: the production catalog is empty (`capability-catalog.ts:85`), no governed-action HTTP surface is wired, and execution presently admits synthetic executor mode only (`governed-action.service.ts:206`).

### A-03 — P2 release gap: verified outcome assertion delivery is best effort

Evidence: action outcome transition is stored before assertion delivery (`governed-action.service.ts:239-240`); `emitObservedOutcome` silently swallows sink rejection (`:395-397`). `infra/governed-action/commercial-evidence.ts:28-38` supplies an in-memory sink for synthetic runs. A crash between transition and emit, or sink failure, can leave a terminal verified action with no observed assertion. Deterministic IDs permit replay but the reviewed runtime does not schedule durable replay. Thus ADR-005's resulting observed assertion is not yet a durable delivery guarantee.

Recommendation: before capability enablement, add a transactionally recorded outbox or an explicit durable reconciliation job with idempotent assertion insertion and visible failure status. Verify crash after outcome commit, failed sink, restart/replay, and duplicate replay. Retained action events preserve underlying evidence, so this is a readiness gap in a disabled foundation, not current active-loop evidence destruction.

### A-04 — P2 research enablement gap: raw-capture grant is not retention enforcement

Evidence: `adapters/adaptive-connectivity/pos-webhook-fixture.ts:46-48` checks explicit workspace authorization and an integer 1–7 day limit, but `:72-76` appends base64 raw bytes to the supplied ResearchReceiptPort without passing an expiry or performing encryption/deletion/audit. The source header explicitly delegates those obligations to the sink and says no such storage is built here. `ports/research-receipt.port.ts:21` only defines append semantics.

Recommendation: keep this synthetic harness restricted. Before authorized real research capture, require a storage implementation and contract carrying retention/expiry, encryption-key reference and audit context; demonstrate automatic deletion within the authorized maximum and audited deletion failure handling. Base64 is transport encoding, not encryption. This gap is already acknowledged by source; it is not a bypass of an active production raw-frame endpoint. The guard alone must not be represented as full ADR-009 compliance.

## Boundaries inspected and retained

Unknown/disabled identities are refused; login does not provision users. Membership admin checks real admin/internal UUID and server workspace. No persistent production WorkspaceRoleLookup composition was found; current implementations are test/static adapters. That reinforces the disabled-foundation verdict.
- Outcome mapping: verified readback becomes an observed, claimed assertion with provider provenance and a technical-event evidence pointer; UNKNOWN and pre-dispatch kill-switch results do not fabricate observations (`action-outcome-assertion.ts:23-34`). It does not invoke commercial-state/outcome mutation. CE-1 remains open; provider result does not become corroborated revenue.
- AIL: `application/integration/config.ts:95-99` defaults off and refuses outside local/test or under NODE_ENV production. Enrollment is admin-only; deprecated issuer path additionally requires explicit opt-in. `upload-validation.ts:8-26` rejects additional keys, including browser payloadHash, binds page and connection/account/workspace to the signed grant, and fixes authenticity/completeness to UNKNOWN. Its SHA-256 retry fingerprint hashes validated metadata rather than message bodies; this is not the A-02 content-digest defect.
- Companion/privacy: `browser-companion/protocol.mjs` checks origin/page scope and exports filtered metadata only, with no body digest. Server observer/message lifecycle use workspace-keyed ContentDigester with kid; tests cover workspace separation and removal of browser-derived hashes. Browser/socket observations remain research evidence, not provider-authenticated truth or permission to write to Pancake.
