# Commercial exception review

COM-01 / R-24: R4 lead discovery and R4.6 contact history already implement the bounded commercial loop. Owner remains distinct from handoff recipient; acceptance transfers responsibility through the existing command. Contact attempts remain human claims, optional evidence does not prove contact, and claimed outcomes do not establish revenue. Work supersession, correction history, owner/version checks, and evidence provenance remain governed by existing APIs. R4.6 explicitly deferred a manager exception workflow; this is the confirmed gap addressed here.

Added a metadata-only manager/admin workspace read under ADR-006, with bounded observations from existing persisted records. It reports absent owner, pending acceptance and elapsed age, known inactive/ineligible or unknown recipient membership, current overdue work, claimed outcome with current open work, absent intake evidence, and unknown context/source. Pending age has no invented SLA threshold. Overdue means the recorded due date passed; it is not a canonical Commercial State transition. Claimed outcomes include Unknown assertions without claiming success or monetary value. Missing contact evidence is not classified as an error. Conversation source remains separate from acquisition lineage; attribution stays UNKNOWN under ADR-008.

One PostgreSQL statement provides a consistent read per page, scoped on every relation to the authenticated workspace. Current work excludes superseded rows; outcomes exclude superseded assertions. EXISTS prevents duplicate claims/work from inflating observations. The current handoff/context use deterministic time-plus-ID ordering. Membership evidence is restricted to the workspace: a recipient with no known membership is UNKNOWN, not presumed inactive or active. A disabled platform user is disclosed only where this workspace already has a membership.

Default scope is real data; synthetic, unknown classification and all require explicit filters. Each request scans at most 101 lead metadata rows and exposes at most 100. Counts describe only the scanned page. UUID continuation can yield pages with no observations; clients must continue when hasMore is true. No workspace total, SLA, financial conclusion, raw payload, evidence pointer, external identity or contact detail is returned. Pages are fresh reads, not a frozen cross-request snapshot; concurrent changes require refresh. No migration, new role/grant, outbound action, attribution logic, or CE-1 resolution.

Verification: 14 targeted tests across service, real Fastify HTTP, and actual private PostgreSQL17 passed. Database used fabricated records only and all 17 existing migrations. Coverage includes role/401/403, query bounds, forged workspace rejection, no-store, explicit memory-mode 503, sanitized failures, real/synthetic/unknown isolation, superseded overdue work, duplicate claims, concurrent reads, current completion changes, recipient unknown/active/disabled, acceptance clearing pending, and UUID continuation. Typecheck, build and lint passed. A standalone operator asset uses textContent and epoch/cleanup guards; integrated module wiring/browser verification belongs to the integration and UX owners. No real provider or pilot adoption evidence is claimed.
