## Implementation and boundaries

SourceObservation separates provider/route/transport account from original native system/page/message and optional conversation/event/revision. Source authority is synthetic_fixture, verification UNVERIFIED; missing times and completeness remain UNKNOWN. Native event ID is never fabricated from message ID. Message bodies stay in accepted raw evidence rather than observation metadata. displayName is synthetic operator input; display names and native identifiers must not be considered anonymous or inherently PII-free, so this remains synthetic-only.

A connection is resolved from the authenticated admin workspace before selecting a decoder. The core checks provider/route/transport account again under a connection row lock. PostgreSQL commits envelope, optional new Lead seed, native mapping, receipt and audit in one transaction. Failure rolls back all effects. Same receipt with changed observation conflicts; concurrent dual routes serialize by workspace/native object. Explicit event+revision collisions compare normalized content and reject disagreement. Different route receipts retain their own immutable raw envelopes.

Without an explicit event ID, the system reports object_aligned, not a proven duplicate provider event. Different native messages remain separate commercial episode seeds even within one conversation and even with identical text. This bounded import policy does not merge Customers, Conversations or commercial episodes. Initial ownership is null unless the admin explicitly checks the creation-time responsibility option; replay and later sightings cannot take over an existing Lead. Existing owner/recipient handoff and mutation policies are unchanged.

Missing native system/page/message produces metadata-only quarantine, no accepted raw/envelope/Lead. Schema failures are categorical400, not a live dead-letter service.
