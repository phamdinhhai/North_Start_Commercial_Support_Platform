# R4.10 ADS-01..04: acquisition, advertising and commerce revenue evidence

Research date: 2026-11-20. Base: `9ffae60`. Public documentation reads only; no credentials, provider account reads, webhook subscription creation, conversion uploads or campaign mutations. This is research plus fabricated financial tests, not connector acceptance. Canonical invariants and ADR-005..009 govern every recommendation.

## ADS-01: evidence taxonomy and authority

| Evidence class | Meaning retained | Meaning never inferred |
|---|---|---|
| Provider advertising metrics | Native metric, object/account, currency, time bucket, attribution configuration, API/report version | Canonical paid revenue, causal ROI or a Lead identity |
| Lead-form/referral touch | Native form/lead/referral/ad IDs and source path when actually supplied | A shared person or Lead from names, phone fragments, campaign titles or free text |
| Commerce lifecycle | Order created/cancelled, payment confirmed, refund created, refund confirmed as separate observations | Created = paid; refund record = cash moved; order value = verified revenue |
| Commercial outcome assertion | Human claim or corroborated assertion through policy/evidence (ADR-005) | Provider status automatically changing Commercial State (CE-1 remains open) |
| Platform revenue attribution | LVP UNKNOWN; future versioned records with model/window/input touches (ADR-008) | Provider conversion counts becoming platform attribution or credit becoming causation |

A provider `Purchase`, GA4 `purchase`, Shopify order, or POS paid flag can be evidence, never a self-authorizing outcome. Preserve conversation source separately from acquisition lineage and revenue attribution (I-02). No CRM identity mapping or merge threshold is settled here (ID-1/ID-2).

## ADS-03: observation identity and money requirements

For Ads slices use workspace + provider + provider surface/API version + account + object + native metric + currency + timezone + reporting date/bucket + attribution window/model/action-report-time + segmentation/query version. Keep provider-reported observation time, event time, click time and conversion time separate. Unknown settings remain explicit UNKNOWN; never fill them from the operator machine. Query changes must not silently collide with an older slice. Late restatement appends another evidence version with retrieval time rather than rewriting history.

The existing `decision-demand/ads-metrics-normalizer.ts` is synthetic only and retains version/surface/unknown dimensions. Its identity tuple does not include every dimension above and its value uses JavaScript number; it is not an accepted financial adapter. This work intentionally does not modify shared source or pretend to close that gap.

Cross-platform spend/ROAS comparison requires compatible currency, time zone, reporting interval and attribution windows; otherwise keep separate. FX needs a separately evidenced rate/date/provider policy, never silent conversion. Lead-form and referral identifiers may support candidate acquisition touches through an explicit provider mapping; missing IDs leave linkage UNKNOWN, with no campaign-text or customer-name matching. Customer, Lead, conversation and order identities remain different.

Financial scale is a field/schema decision plus a currency decision. Ads micros, integer POS amounts and decimal major-unit strings cannot share a universal cents conversion. Keep original amount text and currency. Use exact integer/string arithmetic, reject unsupported currency/precision and unsafe numbers; never parseFloat then round. Distinguish taxes, shipping, discounts, presentment/shop currency and settlement amounts. Partial refunds are individual records, potentially asynchronous, duplicated or reversed; never subtract a refund-created notification as if cash movement were verified. Cancellation does not prove refund.

`product/src/adapters/revenue-fixtures/fabricated-commerce.ts` provides a deliberately small pure fabricated-schema normalizer. It accepts decimal strings only, explicit limited USD/VND/JPY/KWD scales, UTC instants or UNKNOWN event time, explicit valid timezone or UNKNOWN, bounded scoped IDs, and distinct lifecycle kinds. It preserves amount text and unknown Lead/lineage/attribution, returns provider-evidence-only, and has no persistence, routes, credentials, action execution, financial aggregation or production registration. The registry is a fixture choice, not an assertion of provider currency support. Rejected excess precision includes trailing fractional zeros for zero-scale currencies; callers must supply the exact supported representation.

## Evidence and limitations

Public read results support the source matrix; no real sample/customer payload was obtained. Source pages can change; rolling URLs and TikTok rendered portal gaps are expressly recorded. No source repository was copied, so no source-license reuse claim or SDK pin is needed; an SDK shortlist without exact audited pins would add no acceptance evidence. Authentication, plan availability, quotas and API permissions are unverified for any tenant. The fixture deliberately rejects currencies outside its small explicit registry and does not establish verified revenue, attribution, FX, net balance, refund settlement, cross-provider identity or production webhook security. Existing provider financial normalizers remain outside this change.
