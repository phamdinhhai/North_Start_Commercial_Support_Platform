## Meta Page synthetic slice

`product/src/adapters/meta-synthetic/meta-page-fixture.ts` exports `decodeMetaSynthetic(input, expectedPageId?)` and `META_SYNTHETIC_FIXTURE`. The actual-shaped payload is `{object:'page',entry:[{id,time,messaging:[{sender:{id},recipient:{id},timestamp,message:{mid,text}}]}]}` inside an explicitly fabricated wrapper. The restricted contract accepts one incoming text message only; batches, attachments, echoes, edits, deletions, extra fields and tokens are unsupported and fail closed. This is a deliberate fixture subset, not a claim to decode all Page webhooks.

`message.mid` maps to native message identity; it never becomes native event identity. `entry.id` and recipient must agree. Conversation ID stays null because this webhook need not contain it. Optional `syntheticLinkage` requires disclosure `fabricated_fixture_linkage` and remains fabricated provenance. Sender PSID is channel identity, never customer/lead identity. The shared service supplies tenant/connection authorization and intake; the adapter has no domain mutation. Expected connection page must be checked by shared intake even when no optional argument is supplied. Accepted raw fabricated wrapper is detached with structuredClone without normalization. No raw customer evidence, browser digest or provider verification is implied.
