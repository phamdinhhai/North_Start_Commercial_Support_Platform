# R4.10 shared synthetic source intake decisions

This implementation is a flag-off, fabricated-fixture foundation under ADR-007. It does not establish transport connectivity, live provider authority, webhook coverage, completeness, verified actions or revenue attribution. Connections report `SYNTHETIC_ONLY`; accepted observations report `UNVERIFIED`, with completeness `UNKNOWN` in the read model. No polling or transport retry engine is implemented. Receipt replay is the bounded recovery mechanism.

The existing browser integration intake is metadata telemetry and remains separate. Source intake reuses the existing `CommercialEnvelope`, `createEnvelope`, workspace HMAC digester, `createLead`, PostgreSQL transaction service, lead authorization callback and audit table. It does not invoke the manual scenario command because that command assigns a default operator owner.

Synthetic message intake creates a commercial episode seed keyed by `(workspace, native system, page, message)`. This is technical reconciliation of the same native object, not an identity merge. Separate messages remain separate seeds, even within one conversation and even with identical text. Conversation ID is optional provenance; contradictory known IDs fail closed. Pancake IDs are not presumed to be Meta IDs. Explicit fabricated original Meta mapping permits the two fixture routes to align; without that mapping the systems retain separate identities. Customer identity, acquisition lineage and attribution are never derived from message text or provider IDs. Attribution remains unknown. ID-1 and CE-1 remain open.

Each distinct route receipt preserves its own immutable accepted raw envelope and provenance. Replaying a receipt with a changed immutable observation fails. Explicit native event ID plus revision carries immutable event identity; changed normalized utterance, speaker, lifecycle or occurrence time under that identity fails. Route-specific original payloads are preserved separately and may differ. Without explicit event identity, repeated snapshots align only the native object: they do not prove the same event. Distinct events and edit/deletion labels append evidence without reconstructing edit order, current truth or deleting original content. Missing system, page or message identity produces a metadata-only quarantine with no raw retention, lead or accepted envelope, consistent with ADR-009.

One transaction locks the connection (serializing revocation), serializes the native message key, then commits raw envelope, optional seed, native mapping, receipt and audit together. Failure rolls back all. Unique constraints and workspace lead foreign keys protect durable reconciliation. The envelope reference is guarded by scoped construction and scoped read joins; the legacy envelope table has no new composite foreign key added in this change.

Default seeds have no owner, work items, handoffs, actions or outcomes. The optional `claimResponsibility: true` is an explicit authenticated admin command accompanying creation; it assigns only a newly created seed to that admin and is audited. Replays or subsequent observations never change ownership. Existing owner and recipient policies continue to control handoff and Sales actions.

Connection creation, revocation, listing and simulated intake are admin-only and reject demo principals. Evidence reads invoke the existing lead authorization callback inside the application service before reading, audit access and return at most 100 observations with a possible-truncation marker. Internal keyed receipt and raw-content digests are not returned by this service. No credentials, live provider tokens or outbound capabilities are introduced.
